04 / 23
Prompt —— 意图的 DNA
Organ 01/08 · 人写 · 机读
把"你要什么"翻译成模型的语言。Prompt 不是聊天,是接口契约。
Why · 为什么
模型没有你的业务上下文,也读不懂你的沉默。你脑子里 90% 的隐含信息,不写进 prompt 就等于不存在。这是你和模型之间唯一的通道——本质是跨物种沟通协议。
Metaphor · 比喻
Prompt 是写给外星人的需求文档。它不知道你的公司、你的历史、你的潜台词——它只知道你写下的字。所以 prompt 的质量,就是意图的保真度。
How · 怎么做 · 五要素
01
角色——告诉它"你是谁"
02
任务——要什么结果,不要过程散文
03
约束——边界、禁忌、不许做的事
04
示例——给一个"像什么样"的样本
05
格式——怎么交卷:表格?JSON?分点?
Insight · 洞见
Prompt engineering 会过时,Prompt literacy 不会。模型在进化,接口在变薄,但"把模糊意图变成精确指令"永远是人的工作。
05 / 23
Context —— 注意力的血液
Organ 02/08 · 人组织 · 机消费
模型此刻看到的一切,就是它的全部世界。窗口之外,等于不存在。
Why · 为什么
智能发生在窗口内。同一个模型,2K 和 200K 上下文是两种生物。模型没有长期记忆——Context 是它唯一的记忆,也是 AI 时代最稀缺的货币:你往窗口里放什么,决定它有多聪明。
Metaphor · 比喻
窗口不是垃圾桶,是工作台。每塞一条工具输出,就挤掉一条思考空间。高手做的事不是"塞更多",是"删更准"。
How · 怎么做 · 预算管理
01
System 只放不变的——人格、规则、边界,不随任务变
02
历史只留相关的——旧对话总结成摘要,不整段搬
03
知识按需检索——RAG 的本质,是把相关知识搬进窗口
04
外置记忆——Skill / MCP 把知识放磁盘,用时才加载
Insight · 洞见
Skill 的官方机制(progressive disclosure)就是为省 Context 设计的:系统只预载一行简介,正文按需加载——把知识从窗口搬到磁盘。
06 / 23
API —— 世界的接口
Organ 03/08 · 机调用 · 人授权
把现实世界的动作变成可调用的函数。模型不能自己长出手,API 是它与世界之间唯一的物理通道。
Why · 为什么
模型的能力上限 = 它能调用的 API 上限。不会调 API 的模型是"嘴强王者":说得漂亮,什么也碰不到。每一次生图、剪辑、查天气,背后都是某个 API 在干活。
Metaphor · 比喻
API 是"文明接口"——每个 API 背后是一家公司把一项能力商品化。你用的每个 AI 功能,本质是"模型 × 一串 API 的编排"。
How · 怎么做 · 接一个 API
01
读文档——输入、输出、费用、限流,先看懂契约
02
curl 试通——先手工验证,再谈自动化
03
封装成函数——试通的调用包一层,交给 agent 用
04
设计错误处理——重试、降级、超时,坏的时候才见功力
Insight · 洞见
会读 API 文档,等于会读世界的说明书。模型的智商上限,取决于它调用 API 的能力上限——而不是它背了多少知识。
07 / 23
CLI —— 共享的双手
Organ 04/08 · 人机共享
文本命令:人和机器共同认证的操作界面。GUI 是给人类的,API 是给程序的,CLI 恰好两者都懂。
Why · 为什么
这就是 agent 时代 CLI 复活的原因:Claude Code、Cursor、Codex 全是终端形态。Agent 通过 CLI 操作你的电脑,等于借用人类的双手——它不需要 GUI,只需要文本。
Metaphor · 比喻
CLI 是旧技术的第二次生命:1970 年代的界面,成为 2026 年 AI 的双手。因为它简单到机器能懂,严格到机器不会误解。
How · 怎么做 · 最小姿势
01
会读 help——不用背命令,知道去哪查就行
02
会管道——一个命令的输出,喂给下一个命令
03
会看报错——CLI 的报错是结构化信息,不是天书
04
三步变脚本——常用操作写成脚本,就是最朴素的技能
Insight · 洞见
当 agent 借你的手,谁来确认它按哪个按钮?CLI 的普及,顺便把权限问题搬上了台面——这正是护栏存在的理由。
08 / 23
Loop —— 坚持的心脏
Organ 05/08 · 机执行 · 人验收
感知 → 推理 → 行动 → 观察 → 再推理……直到目标达成。单次调用是一次性智力,Loop 给了它坚持。
Why · 为什么
LLM 本身没有意志,Loop 是意志的来源。同一个模型,套上 Loop 就从"答话"变成"干活"。Agent = 目标 + Loop + 工具 + 反馈——心脏不跳,大脑再强也只是摆设。
Metaphor · 比喻
LLM 是大脑,Loop 是心脏。心跳的每一次搏动,都是一次"推理 + 行动";而让心跳停止的,是验收标准。
How · 怎么做 · 给 Loop 装刹车
01
终止条件——什么时候算"完成"
02
最大步数——什么时候算"放弃"
03
反馈信号——怎么知道走对了,还是偏了
04
验收节点——关键步骤,人拍板再继续
Insight · 洞见
LLM 不是 Agent,Loop 才是。Loop 的敌人是 drift——每一步都对,整体偏了。所以 loop 越长,越需要人在关键节点验收。
09 / 23
Skill —— 经验的肌肉记忆
Organ 06/08 · 人固化 · 机执行
把一次成功的"提示词 + 流程 + 工具调用 + 验收标准"固化成可安装的文件包。规范:SKILL.md。
Why · 为什么
LLM 是"每次见面都失忆的天才"。Skill 让经验跨会话存活:一次调通的生图流程、一套验收过的报告模板,装成 Skill 后下次直接调用,不再重新发明。Anthropic 2025-10 发布,2025-12 成为开放标准。
Metaphor · 比喻
肌肉记忆:你不记得当初怎么学骑车,但身体记得。Skill 让 agent 不记得细节,却会做对流程。
How · 怎么做 · 造一个 Skill
01
做一次——把流程完整跑通,别写愿望,写验证过的路
02
复盘——哪几步卡了、怎么解决的,记下来
03
固化——SKILL.md + 脚本 + 参考文件,一个目录装完
04
版本化——git 管理,可以迭代、可以回滚
Insight · 洞见
Skill 不创造能力,只重组能力——生图 skill 背后还是生图 API。它的价值是"封装的复杂度":调用链、参数、验证、失败处理,打包成一次稳定复现。
10 / 23
MCP —— 标准的神经总线
Organ 07/08 · 机协商 · 人配置
Model Context Protocol:让模型以统一方式发现和调用任何工具与数据源。Anthropic 2024-11-25 开源。
Why · 为什么
MCP 之前,每个工具都要定制集成——每个设备一根专属线缆;MCP 之后,一个标准插座。Server 暴露 tools / resources / prompts,Client 即插即用。这就是 agent 时代的 USB-C 时刻。
Metaphor · 比喻
USB-C 之前,你的包里塞满线;USB-C 之后,一根线通吃。MCP 想做的,就是让"连接"成为默认,而不是特权。
How · 怎么做 · 三分钟接上
01
装现成 server——文件系统、GitHub、数据库、浏览器,生态已有一批
02
或包一个自己的——把内部系统暴露成 server
03
接上你的 agent——像插 U 盘,配置一行连接即可
Insight · 洞见
MCP 的技术不难,难在生态——它赌的是网络效应:谁先成为"agent 的 USB-C",谁就拥有整个工具生态。
11 / 23
Agent —— 整台机器
Organ 08/08 · 人定目标 · 机自主 · 人兜底
目标驱动的自主系统:模型 + System Prompt + Loop + 工具 + 护栏。从"问"到"干"的跃迁。
Why · 为什么
聊天机器人回答你,Agent 替你把事做完。但代价是它开始"做决定",于是护栏(权限、确认、只读模式)成为架构的一部分——不是可选项,是结构件。
Metaphor · 比喻
其他七个器官是零件,Agent 是身体。身体不是零件的总和,是"目标"把它们组织成了一次行动。
How · 怎么做 · 从最小闭环开始
01
一个目标 + 一个工具 + 一个验收标准——闭环先转起来
02
跑通再加大自由度——先确定性,后自主性
03
不可逆操作留人工——删、付、发,永远要人确认
Insight · 洞见
Agent 的智能不是模型的智能,是组织能力:上下文里有什么 × 工具库有多广 × Loop 有多纪律。最强的 agent 不是用最聪明的模型,而是最会组织这三样。它不"思考"更久,它只是"坚持"更久,且知道何时刹车。

还有三兄弟:配置文件。
PART 01 · Prompt 从聊天框,走进了仓库
PROJECT · 宪法
AGENTS.md
项目的规则与惯例
路径约定、工作流、禁区、验证标准——跟代码一起进仓库,任何 agent 开工先读它。规则和代码同生共死。
TOOL · 偏好
CLAUDE.md / .cursorrules
每个工具的说明书
同一个仓库,不同 agent 读各自的偏好文件:Claude 读 CLAUDE.md,Cursor 读 .cursorrules。工具不同,口味不同,各读各的。
PERSONA · 自传
SOUL.md
人格、语气与边界
不只规定"做什么",还规定"像谁":说话的口吻、价值观、禁区。让 agent 不只是能干,而是像一个人——你的数字分身。
WHY IT MATTERS
配置文件 = 把 prompt 从"每次打字"变成"默认加载"。同一套意图,写一次,所有会话生效——这也是 2026 年的仓库里,配置文件比 README 还受重视的原因。

冲突一:Context 的零和博弈。
PART 04 · The Three Wars
窗口是硬上限。
聪明和记忆,抢同一块地。
Agent 越能干,越要吃 Context:任务说明、历史、工具输出、检索结果,全要进窗口。塞得越多,每条信息的注意力密度越低——模型没有"读快一点"这个选项,它只有窗口那么大。这是全链路唯一的物理瓶颈。
MOVE 01
检索
只搬相关的。RAG 的本质:不是"塞更多知识",是"精准搬进窗口的那几段"。
MOVE 02
压缩
旧内容总结成摘要。对话历史的正确归宿是"一段摘要",不是原文。
MOVE 03
外置
Skill / MCP 把知识放磁盘,用时才加载。官方 progressive disclosure,就是为这一仗设计的。
VERDICT
未来 agent 的竞争力,不是模型多聪明,而是 Context 工程多好。同样的模型,窗口组织得好,效果差一个量级。
18 / 23
冲突二:确定性 vs 自主性。
PART 04 · 自由度的代价
API 是确定性的,
Agent 不是。这既是优点,也是账单。
确定性(API · CLI):同输入同输出,可测试、可回滚、可审计——适合一切"错了会贵"的操作。
自主性(Agent · Loop):同目标不同路径,不可预测,但能处理新情况——适合一切"没人知道标准路径"的操作。问题只有一个:它俩在同一台机器里。
MOVE 01
Skill 驯化
把验证过的路径固化成模板,用自由度换可靠性——自主的 agent 走固定的桥。
MOVE 02
护栏
权限确认、只读模式、最大步数、不可逆操作留人。护栏不是限制,是结构件。
MOVE 03
验收
关键节点人拍板:loop 越自由,验收点越密。这是对"坚持"的审计。
VERDICT
没有护栏的自主 = 事故的自动化。Agent 成熟度的指标:失控时,它会不会停下来问人。

冲突三 · 封装 vs 透明 —— 群里的原话

"生图、剪辑,不一定就纯靠 skill 搓出来的——不算是'百宝箱',最多是'封装复杂度'的作用。它背后还是要接很多其他的东西(如生图 API)。"

AI 交流群 · 2026
关于「Skill 是不是百宝箱」的讨论
Skill 和 MCP 都在封装复杂度——这是杠杆,不是魔法。封装越厚,上手越容易,黑盒越深。原则:对用户封装(一句话触发),对开发者透明(能看、能改、能拆)。

客户端,还是 API?
PART 05 · 实战
生图、剪辑这些能力——
用 ChatGPT / 豆包客户端,还是接开发者平台?
TRACK A
客户端
固定成本 ≈ 订阅费,边际成本 ≈ 0,上手最快。能力被产品经理替你封装好了,但不能改参数、不能批量、不能自动化。
用量小 → 用这个
TRACK B
API + 平台
按量付费,单价低,可控可批量可自动化。代价:要读文档、要管密钥、要处理限流与错误——你接手了"复杂度"。
用量大 / 要自动化 → 用这个
TRACK C
Skill 中间层
Skill 不决定你用哪个底层——它让"换底层"变便宜:今天接豆包,明天接通义,skill 不动。你的工作流被固化,底层随时可换。
想沉淀工作流 → 加这层
VERDICT
这不是技术问题,是经济学问题——两条成本曲线的交叉点,就是你的切换点。
群里的原话:「如果使用量比较小,ChatGPT 和豆包客户端就能 handle;用量大,或者想试 API,就得找开发者平台、开放平台。」——先跟 AI 聊,再决定接不接 API。

一个任务,八个器官全上。
PART 05 · 实战拆解
01
Prompt意图入机
写下目标、范围、输出格式——模糊想法变成指令契约。
02
Context血液预算
只给相关背景,别全塞;旧资料先总结,再进窗口。
03
Agent组织执行
拆任务、排顺序、分配工具——机器正式上线。
04
Loop心脏跳动
查 → 记 → 验,直到清单齐;卡住就重试,超步就停。
05
MCP神经连接
接搜索与数据源——工具即插即用,不用定制集成。
06
CLI · API双手干活
跑脚本、处理表格、调服务——现实世界被触碰。
07
Skill肌肉记忆
整套流程固化——下个同类任务,直接复用,不再重新发明。
08
Verify验收
人检查结果,不对就回去;关键动作,人拍板。
少一个器官,任务也能干;全部咬合时,它从"帮我写"变成"替我做,并且下次还会"。

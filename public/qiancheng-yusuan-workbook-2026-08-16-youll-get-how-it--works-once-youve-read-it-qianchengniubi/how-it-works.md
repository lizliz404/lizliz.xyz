## 一句话

这本工作簿不是数据库。它是三件事叠在一个 `.xlsx` 里：

**填报工作流**（拆表、发给部门、收回、签字）  
**计算引擎**（12,341 个公式，跨 sheet 引用）  
**合并报表**（部门 → 事业部 → 法人公司 → 集团）

系统要替代的是前两件事的「用邮件搬文件」部分。第三件事的版式，财务明确要继续能导出成他们熟悉的 Excel。所以「替代 Excel」= **替代总线，不是消灭导出，也还不能宣布已经替代。**

正式切的条件在 `GOAL.md`。代码全绿不能替财务签字。`npm run verify:release` **预期失败**——它是放行闸门，不是坏掉的测试。

## 表是怎么长出来的

Excel 里一张「部门预算表」不是数据库里的一行。它是这样来的：

```text
去年那张部门 sheet（或一张空白模板）
    │  财务另存 / 复制工作表 / 改部门名
    ▼
部门主管填：客户 × USD × 毛利率、~21 项费用、人员、签字
    │  邮件来回；财务贴回 145 张的那一本
    ▼
事业部汇总 sheet 用公式把这一列加进去
    │
    ▼
经营费用汇总 → 公司总表 13 行 → 汇总版
```

所以「形成」有两层，别混：

1. **形状从哪来**：抄去年的格子。标准部门多数是 66×17；香港系常是 59×17；提点是 56×36 / 50×37，不是把行数拉长一点。职能表、78 行运营明细、13 行总表，从第一格起就不是同一台机器。
2. **今年的数从哪来**：人填进这张复制出来的 sheet。公式再把它滚上去。没填的格子在 Excel 里常常看起来像 0，合并会把「还没交」和「真是零」混成一件事。

系统把这两层拆开了：

```text
先有组织
  Entity（法人，isRoot=母体）
    └── Division（事业部；方可以管三个）
          └── Department（填报最小单位）
                ├── budgetKind = STANDARD | COMMISSION
                └── revenueMode = STANDARD_USD | CNY_GROSS

再有年份 BudgetYear（2025 封存 / 2026 在编 / 2027 下一轮）

财务发任务
  → 给今年有效部门各建一份 Budget（状态：未开始）
  → 运营/职能：按 TableDef 克隆出今年的 TableInstance，指派到人

部门填的是关系表，不是复制 Excel
  标准：SalesLine + BudgetExpense + StaffLine
  提点：CommissionRevenueLine + BudgetFundingLine（提点率不是毛利率）
  职能/公司费用：TableInstance.rows（万元 + 备注）
```

主链对象只有一种：**部门预算表**。三种表型共用一个门、一套审批状态，不拆三个产品。运营表、公司总表是另一类对象（`TableDef` / `TableInstance`），喂进合并，不跟部门表抢导航。

空表要往前走，必须有人勾「今年确实为零」。再改内容会清掉这次确认。任何缺值都不能默认为 0。

## 层级：一张图

```text
集团合并 / 汇总版          ← 财务拼装；老板签字栏在这一层
        │
        ├── 前程公司总表（13 行）     母体；r6 管理费、冲回、扣奖都算在它头上
        ├── 各子公司公司总表          格联 / 联辉 / 钜明 / 香港联明…
        └── 经营费用汇总              部门经营费用滚到公司层之前的中间表
                │
                ├── 事业部汇总        经理看的并排表；常带 预算|决算|预算 三列
                │       │
                │       └── 标准业务部门填报表     客户 × 美元销售 × 毛利率
                │                                 + 费用 + 奖金 + 人员
                │
                ├── 提点/提成部门                 销售额 × 提点率；可追溯到来源部门
                ├── 职能部门（人力/财务/风控IT）   单位是万元；有收入侧和编制依据
                └── 公司运营费用明细（78 行）      总部自己的开销；折旧/IPO 都在这里
```

对应到系统里的组织实体（`next/prisma/schema.prisma`）：

```text
Entity（法人主体，isRoot=母体）
  └── Division（事业部）
        └── Department（填报最小单位）
              └── Budget（某一年度的那一份）
```

事业部在旧 PocketBase 里只是部门上的一个字符串。新系统升成独立实体，否则「方管三个事业部」这种事只能靠字符串碰运气。

母体是 `Entity.isRoot`，不是名字叫不叫「前程」。别家公司没有叫前程的主体时，合并必须仍能算。子公司**不套母体那套公式**：r1–r5 由自己的部门滚上来；r6 / r10 / r11 / r12 是各家签字的政策数（格联 r10×0.8、钜明税率 0.835 这类），只能照抄不能重算。

政策数没确认的主体**不进合并**。宁可少一家，也不能给一个看起来很真的错数。

## 表型：看起来都叫预算，其实不是同一种表

`SOURCE_COVERAGE` 的分布（145 张）：

| 表型 | 张数 | 单位 | 谁填 | 喂给谁 |
|---|---:|---|---|---|
| 标准业务部门预算 | 80 | 元；销售是 USD | 部门主管 | 事业部汇总 → 经营费用 → 公司总表 r1–r5 |
| 事业部/公司部门汇总 | 13 | 万或元，看具体表 | 公式；经理看 | 公司层 |
| 部门/区域汇总中间表 | 12 | 多为万 | 公式 | 公司总表 / 合并 |
| 法人公司总表 | 9 | 万 | 混合：r1–r5 滚上来，r6–r13 政策+喂养 | 集团合并一列 |
| 公司级费用明细 | 7 | 万 | 财务或职能 | 公司总表「减:公司管理费用」等 |
| 历史业务部门模板 | 7 | — | 不填 | 沿用结构，不是当年数 |
| 职能部门预算 | 5 | **万** | 职能经理（指派） | 母公司管理费用明细的一条 |
| 点数/提成部门预算 | 4 | 元 + 提点率 | 开发/市场 | 不能塞进「客户×毛利率」 |
| 集团/多主体合并表 | 3 | 万 | 财务拼装 | 终点 |
| 空白占位 | 3 | — | — | 候选排除，财务没签字前不能当没了 |
| 递交状态总览 | 1 | — | 财务 checklist | 编制进度 |
| 子公司管理费与关联政策 | 1 | 万 + 比例 | 财务定比例 | 对前程是收入，对子公司是费用 |

幻灯条形图把「事业部汇总 13 + 区域中间表 12」收成「汇总中间 25」，把「历史 7 + 空白 3 + 总览 1 + 政策 1」收成「其余 12」。加起来仍是 145。张数不等于难度：漏建模的风险在短的那几根。

异同的判断标准不是「表名像不像」，是三件事：

1. **收入怎么进**：客户×USD×毛利率 / 人民币收入 / 提点率 / 职能服务收入
2. **单位**：元 vs 万元。混用是 Excel 原罪，系统必须在界面上标死
3. **行是固定的还是自由加**：公司总表 13 行是固定骨架；职能表是自由科目 + 备注

## 标准部门表：这台机器的原子

一张典型业务部门表在算这件事：

```text
客户行:  销售额 USD × 毛利率 → 毛利 CNY（× 做账汇率）
费用:    ~21 项经营费用（工资、运费、差旅、招待…）
自动项:  税金 / 研发费用 / 业务管理费 —— 按销售额×费率算，可手工盖
奖金:    公式 = (毛利 − 费用) × 80% × 25%；财务几乎总会改成拍板数
人数:    人员行；编制人数看「人数」列，不是分配比例
净利:    毛利 − 费用 − 奖金
```

签字栏在 Excel 里是「业务主管 / 事业部经理」。系统改成状态机（见下节），打回回到可改。

同一套「部门」里还有两个变体，不能假装没看见：

- **人民币收入部门**（`revenueMode = CNY_GROSS`）：不填美元销售，直接填人民币收入。实测「公司综合（宁波联明）」这类。
- **提点部门**（`budgetKind = COMMISSION`）：收入 = 项目销售额 × 提点百分比；提点来源能追溯到 A02/A03… 具体业务部。硬塞成客户行会丢掉提点率和来源。原件奖金格是负号（展示）；进系统归一成**正的奖金成本**，否则净利公式会把利润加回去。隐藏子表仍登记在覆盖矩阵里，hidden ≠ 作废。

非标费率是部门级的，不是全公司一个数。例如公司七部业管 2%（其余常见 1%），研发可以是有效的 0。`null` 才是「没配」。

## 一条真表：格联开发部 A21 怎样变成公司总表的一行

80 张标准部门都走「客户 × 美元 × 毛利率 → 本公司 r1–r5」。下面这一张**不是**那种形状。用它看「填完的 sheet」怎么变成预算。数字是原件缓存的观察性样例（`audit/SPECIAL_BUDGET_CONTRACT.md`），2027 规则财务还没签死，不能当最终口径。

sheet：`格联开发部A21(金）`（56×36，提点；不是 66×17）

收入怎么进：

| 项目 | 预计销售 USD | 提点 | 开发收入 CNY |
|---|---:|---:|---:|
| ChefRobot智能厨房产品 | 7,000,000 | 5.0% | 2,450,000 |
| (业务部)市场开发部提点千5 | 30,000,000 | 0.5% | 899,500 |
| 项目收入小计 | | | **3,349,500** |

提点千 5 那一行还能追溯到具体业务部（A02 / A03 / A05 / A07… 合计 899,500）。硬塞成「客户 × 毛利率」会丢掉率和来源。

整张主表滚完（D 列）：

| | 原件 |
|---|---:|
| 项目收入 D16 | 3,349,500 |
| 公司投入 D17（四个业务部的研发费） | 1,429,764 |
| 奖金 D18 | 格里 **-490,000**（展示负号）；系统存正成本 490,000 |
| 支出 D39 | 4,105,600 |
| 利润 D40 | **183,664** |

Excel 公式链——这就是「变成预算」：

```text
2025公司总表(格联）(金）!C10
        = 格联开发部A21(金）!D40 / 10000
```

除以 10000：部门表是**元**，公司总表是**万**。姊妹表 `格联市场部A22` 走另一条：`经营费用汇总(格联）!L28 = -A22!D40`（利润 27,500 元，展示奖金 -630,000）。

系统对位：`BudgetResultFeed` 在 2025 已落库。A21 利润**覆盖**格联 r7；A22 利润以负数加入格联 r3。2027 还去不去这两行、奖金还是不是 `-D3/5` / `-D16/2`，财务没拍板。两张隐藏子表奖金公式不同，hidden ≠ 作废。

## 13 行利润表：下层怎么滚上来

公司总表（和合并报表同一套行）现在进了 `table_lines`，不再只靠代码常量。行的**名字和解释**可配；每一行**怎么算**仍在外贸出口包里。引擎按 `r1`…`r13` 的位置认行，key 不能乱改。

| 行 | 标签 | 怎么来的 |
|---|---|---|
| r1 | 预计完成销售收入(USD) | 各部门销售额加总，减去关联交易 |
| r2 | 预计毛利 | 销售额 × 毛利率 × 做账汇率 |
| r3 | 减:预计发生经营费用 | 各部门费用加总 |
| r4 | 减:可能产生的奖金 | 公式或手工拍板 |
| r5 | 预计税前业务净利润 | r2 − r3 − r4 |
| r6 | 减:公司管理费用 | **喂养**：职能表 / 公司费用表明细合计盖过来；也可手填 |
| r7 | 加:研发费用冲回 | 部门已计提的研发费，集团加回来 |
| r8 | 加:公司管理费用冲回 | 业管费 + 人员管理费，集团加回来 |
| r9 | 加:理财 | 手填 |
| r10 | 税前净利润 | 营业利润 − 管理费 + 冲回 + 理财（母体另有「扣管理奖金」口径） |
| r11 | 税后净利润 | × 税后留存系数 |
| r12 | 扣减少数股东权益 | 子公司利润里不属于本集团的部分（比例在 `Entity.minorityRate`） |
| r13 | 合并体系前程税后净利润 | r11 − r12 |

三条最容易搞错（`rollup-query.ts`，对着原表口径搬的，不是新发明）：

1. **子公司不套母体公式。** r1–r5 来自该公司自己的部门；r6 / 分成 / 税率 / 少数股东是各家政策数。
2. **明细表会盖掉手填的政策数。** 子公司填了公司费用明细，r6 用明细合计；表空（只有结构没有金额）才回落手填。空合计必须是 `null` 不是 `0`。
3. **政策数没确认的主体不进合并。** 提点预算的年度去向缺失或未确认，结果暂不进公司表，但必须点名。

少数股东比例原来只写在 Excel 行标题里（「扣减少数股东权益(25%)」）。系统现在能显示比例、校验手填额，**不自动覆盖**——钜明是「45.5% 及补税 0.085」，实测约占税前 51.05%，不是单一比例能表达的。

## 喂养：这张表填完，去盖掉哪个数

Excel 里这是跨 sheet 公式。系统里这是 `feeds` 表。规则读唯一入口：`next/src/lib/budget/feeds.ts`。

机制：

```text
来源表（TableInstance.rows 已填金额的合计）
    │  pick = 点名某一张  或  按表种类整批
    │  agg  = 只加填了的行；一行都没填 = 这张表还没填 = 不盖目标
    ▼
目标  母公司管理费用明细的某一行     或     某公司总表的某一行（如 r6）
    模式 OVERRIDE（盖掉）或 ADD（累加）
```

关键坑：空表合计必须是 `null` 不是 `0`。返回 0 会把目标行手填值盖成 0，报表少一块。

前程这套配出来大致是：

| 来源 | 目标 |
|---|---|
| 部门预算（行业包汇总） | 本公司总表 r1–r5 |
| 职能部门费用表（AD_HOC，指派到人） | 母公司管理费用明细的一条 |
| 公司运营费用明细 | 母公司「行政综合」那条 |
| 公司费用明细（每家公司一张） | 该公司总表 r6 |

提点另有 `BudgetResultFeed`：2025 已落库的两条是 A21 利润覆盖格联 r7，A22 利润以负数加入格联 r3。2027 去哪一行、收入是否与业务部门重复，仍要财务确认。

配错要当场拦住：指向不存在的行、两张表抢同一行、喂养成环。`feed-check.ts` 做这事。

## 预算实际怎么做：Excel 六站 vs 系统流水线

来自 `audit/数据流转与责任地图.md`，已逐站对过原件：

```text
S1 部门明细（元）           部门主管填 + 纸面双签
S2 事业部汇总（公式）       经理看并排；财务按月回填决算列
S3 职能与公司层（万元）     职能经理自表；财务填 78 行运营明细；
                           子公司管理费 = 出口额 × 比例
S4 子公司公司总表           子公司负责人对 r6–r13 政策数负责
S5 汇总版                   财务拼装 + 关联抵消 + 多口径并排 + 董/总签字栏
S6 决算回填                 财务把实际写回 S2（销售 / 毛利 / 经费 / 净利）
```

系统对位（产品句：发任务 → 填 → 提交 → 审核 → 定稿 → 导出）：

| Excel | 系统 | 差在哪 |
|---|---|---|
| 拆表、发邮件 | 财务发任务，生成今年的 `Budget` / `TableInstance` | 对。任务入口在财务「今天」 |
| S1 填 + 双签 | 部门填自己的表，提交 | 对。纸面签字弱化成留痕 |
| S2 催交 / 经理看 | 负责人审已提交的表；范围内催交 | 基本对。事业部汇总三列并排（去年预算 \| 去年决算 \| 今年预算）系统没有同等现场 |
| S3 职能 + 78 行 + 比例 | 运营表 + 指派 + `Entity.mgmtFeeRate`（出口额现算） | 对 |
| S4 政策数 | 曾错位成「只有财务能点」；后来下放给子公司负责人，只见自己公司 | 对位已改过 |
| S5 合并 + 导出 | 报表页 13 行 + 导出熟悉版式 | 有。董/总「报送形态」（去运维噪音）是产品问题不是计算问题 |
| S6 决算四指标 | 预算 vs 实际，接宏桥账面 | 有线。指标比 Excel 四指标窄；导出里往年决算块仍空着（原表那格有数） |

状态机只在 `permission.ts` 定义一次。页面能不能点、服务端能不能写，是同一个函数：

```text
未开始 →（部门填）填报中 →（部门交）已提交
      →（负责人审）经理已审 →（财务定稿）已定稿，数字锁住
打回：已提交 / 经理已审 → 被打回 → 部门再改
已定稿要改：财务先撤回定稿，回到经理已审。合并报表会跟着变。
```

经理只审不改数字。定稿是锁数字、拿去对外，只能财务按。人事只看人数和工资口径，不填表、不审批。2025 年度封存，谁都不能改。

角色四词：部门 / 负责人 / 财务 / 人事。主链最多四项，顺序就是故事：今天 → 预算表 →（仅财务）报表。运营表、预算 vs 实际、人员口径、组织与设置、Excel 对账、帮助，活在「更多」，不跟主链抢第一击。

## 三套最容易混的口径

### 1. 单位

部门填报表用**元**。职能、公司运营、公司总表、合并用**万元**。Excel 里靠人脑切换。系统 `TableUnit = YUAN | WAN`，界面必须写死，不能靠「大家应该知道」。

### 2. 币种与汇率

- 部门销售：USD
- 毛利、费用、奖金、公司层：CNY
- 做账汇率 `EntityPolicy.bookingFx`：算部门预算用（2026 常见 6.8）
- 折人民币 `Entity.fxToRmb`：合并时把成员公司本币折回来（HTH 7.7 这类）
- 这两件事不是同一个数

Excel `各部门汇总` C121 欧元汇率是 **7.7**。系统 `fx_rate` / `company_fx` 都是对美元。德国/欧洲部门一进合并会用错币。

### 3. 年份

不是「这本表记去年一年」。

| 年 | 角色 |
|---|---|
| 2025 | 封存历史底账，来自这本原件 |
| 2026 | 在编预算，来自旧 PocketBase 同步 |
| 2027 | 下一轮启用范围，不和前两年混算 |

事业部汇总表标题经常是「预算、决算一览表」，三列并排：去年预算 | 去年决算 | 今年预算。决算在 Excel 里是一等公民（134/145 张 sheet 出现过「决算」）。系统「预算 vs 实际」接的是宏桥账面；完成度是「账面实际 ÷ 同期折算预算」（已结月份直线折算），管理参考，不是绩效结论。映射不完整时集团完成度必须空着，不能给一个看似真实的百分比。

页面上的「完成度」其实有三种，不是一回事：填报流程走到哪、预算 vs 实际、源表 72/145 覆盖。来源见 `docs/DATA_PROVENANCE.md`。

## 关联交易与子公司管理费（一对镜子）

**关联交易**：集团内部自己卖给自己。合并时要从销售收入里减掉。Excel 是逐笔，不是一个总数。原件 `各部门汇总` r129–134：

| 部门 → 对手方 | 金额 |
|---|---:|
| 代运营 A36RB → RIBELLI | 1,590 |
| 市场部 A51 | 210 |
| 市场部 A53 | 196 |
| 市场部 A60 | 300 |
| 市场部 A59 | 1,055 |
| 合计 | **3,351** |

汇总版 r32–38 用公式再算一遍。系统必须只留 `Intercompany` 一份。减一次还是沿源表双减，见财务拍板单，不在这编口径。

**子公司管理费**：母公司按各子公司出口额 × 比例收费。对前程是收入，对子公司是「付前程费用」。原件 `2025子公司管理费明细`（观察性样例）：

| | 出口额 | 比例 | 人员管理费 | 合计 |
|---|---:|---:|---:|---:|
| 钜明 | 5,550 | 0.3% | 140 | 256 |
| 格联 | 3,000 | 0.5% | 107 | 212 |
| 宁波联明 | 1,350 | 1.0% | 44 | 138 |
| 联辉 | 8,000 | 1.0% | 197 | 757 |
| | | | | **1,363** |

比例现在存在 `Entity.mgmtFeeRate`，出口额从当年预算实时算，不再写死在代码里。子公司侧对应「付前程费用」。

公司运营费用明细（78 行）同一本原件：大类合计 2,433（其中折旧 1,000、IPO 200），减去补贴和子公司管理费收入 1,363 之后总计 1,860。这张表喂母公司「行政综合」，再进 r6。不把 24 个大类在这里再抄一遍。

## 系统把 Excel 收成了什么 —— 以及什么还没

```text
Excel 一张 sheet
    │
    ├─ 形状像「标准部门」  → Budget + sales/expense/staff 关系表
    ├─ 形状像「提点」      → COMMISSION 专用行（commission revenue / funding）
    ├─ 形状像「职能/公司费用」→ TableDef + TableInstance（可建、可指派、可喂养）
    └─ 形状像「公司总表」  → TableLine 13 行 + 行业包计算
```

| 系统已经做了 | 还在 Excel / 门禁里 |
|---|---|
| 拆表、发任务、收回、状态机 | 73 张源表没收口（29 张要财务选：2027 启用 / 归档 / 排除） |
| 标准 / 人民币收入 / 提点 三种表型 | 未识别字段变成 0 —— 禁止；缺值必须看得见 |
| 喂养表、空合计是 null | 6 个业务口径待拍板（关联抵消、职能收入、提点冻结、历史实际、完成度曲线等） |
| 13 行合并 + 格子下钻 | 27 条账面归属未收口；映射不完整时完成度空着 |
| 导出熟悉版式 | 导出里往年决算块仍空；Excel 四指标未齐 |
| 权限在服务端，不靠藏按钮 | 董/总报送纸、编制依据在业务部门费用格、欧元汇率位 |
| 受控试点（`yusuan.hanzilla.co`） | `verify:release` 必须 BLOCKED；独立验收、部署、真实轮次尚未冒充已完成 |

可配置三层（`数据模型方案.md`，已经部分落地）：

| 层 | 放哪 | 例子 |
|---|---|---|
| 必须可配 | 数据库 | 有哪些表、行标签、谁填、喂给谁、公司/部门/人、费用项目、汇率 |
| 行业包 | 代码 | 毛利率法、关联抵消、成员折算、扣管理奖金、审批流 |
| 不该配 | 代码+权限模型 | 数据怎么存、谁能看谁；配了只会出事 |

不做全公式引擎。财务不会写表达式，算错了没人看得出来，等于重做 Excel。

可搬运性已经有的钩子：

- `BRAND` / `BRAND_FULL` 环境变量：换皮不改代码
- `Entity.isRoot`：母体不靠名字
- `TableDef` / `Feed`：换一家公司先配表和喂养
- 空白公司验收：只配数据跑出完整预算，前程的数一格没动（方案里记录过）

还没承诺的：变成市面上那种通用 FP&A SaaS。行业包仍是外贸出口。分布式子系统 vs 塞进大 OA，数据模型已经按「可独立部署的预算域」切了；部署拓扑是运维决定，不是再做一套 schema。

## 本地能很快 work，云端难在哪

本地（已写进 README）：

```bash
docker compose up -d --wait db   # Postgres 16，不是 Cloudflare
cd next && cp .env.example .env
npm ci && npm run setup:local && npm run dev
```

演示库是虚构数据。PocketBase 是**旧系统**的库；新系统是 **PostgreSQL + Prisma**。昨天能跑，是因为 Docker 把有状态的数据库带起来了。演示账号只存在于本地引导库，生产拒绝。

Cloudflare 扛不住这套 backend 的原因很具体：

| 工作负载 | 为什么 Workers 不够 |
|---|---|
| Prisma + Postgres 长连接 | Workers 是短请求、无持久连接；Prisma 引擎还分平台二进制 |
| `npm run import` / 对拍 / ERP 同步 | 分钟级任务，不是 30s isolate |
| 导出 50+ sheet 的 xlsx | CPU + 内存，边缘算不起 |
| 会话、权限、审批写路径 | 要事务和真实数据库，不是 KV |

现网试点已经在 `yusuan.hanzilla.co`（长进程 + Postgres）。这是对的形状。Pages/Workers 最多将来托管**这份讲解 HTML** 或登录前的静态页，不要幻想把预算引擎搬上去。主站讲义挂在登录后 `/help/architecture`。lizliz.xyz 子路径若出现，只是镜子，本轮不发。

可扩展部署的诚实选项：继续现有 VPS/容器（hanzilla.co 子域名），或 Fly/Railway 一类「有 Postgres 的容器平台」。子域名当子系统、或反向代理进大 OA，对这套代码是同一件事：`basePath` + 环境变量。不要为「会不会并进 OA」先拆微服务。

## 当前到底做得怎么样

工程上：不错。有类型、有关系模型、有喂养表、有权限状态机、有逐格对拍门禁。这不是玩具 demo。

业务上：受控试点。145 张盘过了，72 张源验证，73 张没收口。正式替代仍被诚实阻塞。

用户感受上：填报页边填边算、审批按钮写后果、空表提交要勾确认——这些已经比多数内部系统强。缺的是「我改了没保存」的恐惧处理（仍要点保存），以及登录后 10 秒内「我该填哪张表」。

不要被这些证据骗成「已经替代 Excel」：

| 已有证据 | 能证明 | 不能证明 |
|---|---|---|
| 145 张源表清单 | 没有整张表从盘点中消失 | 每张表的业务含义都已决定 |
| 72 张源验证 | 这些表在既定合同内有来源与守恒 | 剩余 73 张可以忽略 |
| 单测和 `npm run verify` | 已建模路径没有已知回归 | 财务已接受所有口径 |
| Excel 导出对拍 | 已覆盖格子没有漂移 | 原工作簿 145 张语义全部迁移 |

## 系统说已经滚上来时，可以问

页面好看、试点能点、代码全绿，都不是放行。用这些问题顶：

1. **这张表是 145 里的哪一张？** 72 张对过源，还是 73 张没收口？hidden 的仍可能被引用。
2. **空的还是零？** 没填就不该盖手填数。完成度映射不齐必须空着，不能编一个百分比。
3. **元还是万？USD 还是 CNY？** 做账汇率和折人民币是两个数。欧元格子在原件是 7.7，系统还缺位。
4. **这是 2025 底账、2026 在编，还是 2027 范围？** 三列并排的「决算」不是系统里那条窄的实际数。
5. **谁盖掉了这个数？** 喂养是 OVERRIDE 还是 ADD？空表有没有被当成 0？政策数这年确认了没有？
6. **这是标准表、人民币收入表，还是提点表？** 提点率不是毛利率；奖金原件负号进系统是正成本。
7. **verify:release 过了没有？** 没过就不能对财务说 Excel 已替代。过了也只是两类工程数据门禁，不是签字。

代码全绿、页面好看、试点能点，都不是放行。
